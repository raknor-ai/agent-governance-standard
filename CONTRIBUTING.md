# Contributing to the Raknor Agent Governance Standard

## v1.1 Proposal Window

The Raknor Agent Governance Standard is maintained under Section 14's commitment: **proposed changes are published for comment before adoption.**

This repository is the venue for that process. The v1.1 proposal window is now open.

## How to Propose a Change

1. **Open an issue** using the [v1.1 Proposal](../../issues/new?template=v11-proposal.yml) template.
2. **Identify the section** of the v1.0 standard your proposal affects.
3. **Quote the current text** so reviewers can see what you are proposing to change.
4. **State your proposed change** clearly -- what should the text say instead, or what should be added.
5. **Provide rationale** -- why the change is needed, what problem it solves, and any evidence or implementation experience that supports it.

## Scope

Proposals may target any part of the v1.0 standard: controls, thresholds, methodology, definitions, scope, or structure. Proposals that add new controls, modify existing requirements, or change certification thresholds are all in scope.

Cross-references to external implementations, specifications, or standards are welcome as supporting evidence. Proposals grounded in operational experience or disclosed implementation gaps carry more weight than abstract arguments.

## What Happens Next

- Proposals are discussed in their issue threads during the comment window.
- At window close, the maintainers review all proposals and publish a disposition for each: accepted, accepted with modification, deferred, or declined -- with reasoning.
- Accepted proposals are incorporated into the v1.1 draft, which is published for a final review period before adoption.

## Out of Scope

- Pull requests against STANDARD.md during the proposal window will not be merged. The proposal-then-draft process ensures all changes are reviewed together.
- Proposals that require changes outside the standard's text (tooling, infrastructure, certification process) are noted but handled separately.
